## 설치와 명령

Node 20.19 이상과 npm을 사용하며 모든 명령은 저장소 루트에서 실행한다.

```sh
npm ci
npm test
npm run build
```

`npm test`는 Vitest를 한 번 실행하고 종료한다. `npm run build`는 TypeScript 검사 후 `frontend/dist/`에 정적 산출물을 만든다. 둘 다 개발 서버를 상시 실행하지 않는다. GitHub Actions의 프론트 검사도 이 명령을 사용한다.

화면을 실행하기로 한 사용자가 직접 개발 서버를 시작한다.

```sh
npm run dev
```

접속 주소는 Vite 출력으로 확인한다. 브라우저 루트는 `/#/landing`으로 이어지고, `/#/home`은 로그인·취향 완료가 필요하다.

## 로그인해서 화면 확인

1. VS Code 터미널에서 프로젝트 루트로 이동한 뒤 `npm run dev`를 실행한다.
2. 터미널에 출력된 `Local:` 주소를 연다. 다른 프로젝트가 기본 포트를 사용 중일 수 있으므로 출력된 실제 주소를 사용한다.
3. 상단 로그인 또는 시작하기를 누른다. 처음 사용하는 경우 회원가입 탭에서 닉네임·테스트용 이메일·8자 이상 비밀번호를 입력하고 로컬 체험 안내를 확인한다.
4. 아티스트 5개·곡 10개·장르와 무드를 선택하면 개인 Home과 나머지 화면을 볼 수 있다.

미리 제공된 공용 로그인 계정은 없다. 기본 mock 모드에서는 프론트만 실행하면 가입·로그인할 수 있으며, 별도 백엔드·DB 실행이나 실제 이메일 인증은 필요하지 않다. 실행한 서버는 터미널의 `Ctrl+C`로 종료한다. 의존성 누락 오류가 나면 루트에서 `npm ci`를 한 번 실행한 후 다시 시작한다.

## 기본 로컬 모드

기본값은 `VITE_API_MODE=mock`이다. 계정·취향·초대·요청은 같은 출처의 브라우저 저장소에만 존재한다. 초기 추천 사용자는 없고, 음악 선택용 예시 메타데이터만 있다. 음악이 없으면 직접 추가할 수 있다.

| 저장 위치      | 키                           | 용도                              |
| -------------- | ---------------------------- | --------------------------------- |
| localStorage   | `tunit-browser-demo-v1`      | 계정·카탈로그·취향·초대·관심·연결 |
| sessionStorage | `tunit-browser-demo-session` | 탭별 로컬 로그인 상태             |
| sessionStorage | `tunit-brand-intro-v2`       | 해당 탭의 인트로 완료 표시        |
| localStorage   | `tunit-follow-{userId}`      | P1 계정별 로컬 팔로우             |

기존 `tunit-profile`과 이전 `tunit-brand-intro-v1` 표시는 덮어쓰거나 삭제하지 않는다. 체험용 비밀번호는 PBKDF2 단방향 값으로 보관하지만 브라우저 데이터는 서버 인증 경계가 아니다. 실제 서비스의 비밀번호는 입력하지 않는다.

## 두 계정으로 흐름 확인

1. 계정 A로 가입하고 아티스트·곡·장르·무드를 입력한다. 혼자 탐색은 비공개로도 가능하다.
2. 친구 비교를 체험하려면 취향 공개를 켜고 초대 화면에서 비교에 동의한 뒤 링크를 복사한다.
3. My Taste에서 로그아웃하고 같은 브라우저에서 계정 B를 가입한다. B도 취향 입력·공개 설정을 마친다.
4. 초대 링크로 돌아가 비교에 동의하면 두 계정의 궁합을 확인할 수 있다.
5. 상대 공개 프로필에서 관심을 보내고, 보낸 계정에서는 취소, 받은 계정에서는 수락·거절을 확인한다.
6. 취향 수정·삭제·비공개 후 다시 조회해 추천·비교 반영을 확인한다.

한 명만 가입한 상태에서 후보 0명은 정상이다. 다른 탭에서 변경한 내용은 상태 확인 버튼이나 재진입으로 갱신한다. 탭을 복제하면 로그인 상태가 복사될 수 있으므로 어느 계정인지 먼저 확인한다.

다른 기기·시크릿 창·브라우저·포트는 저장소를 공유하지 않는다. 로컬 초대가 다른 기기에서 동작하는 것으로 검증하지 않는다. 외부 듣기는 음악 검색을 새 탭으로 열며 앱 안에서 음원을 재생하지 않는다.

## 환경변수와 향후 HTTP 모드

예시는 [frontend/.env.example](../frontend/.env.example)에 있다. 실제 Spring API가 준비되면 개인 `frontend/.env.local`에 다음 공개값을 설정한다.

```dotenv
VITE_API_MODE=http
VITE_API_BASE_URL=/api/v1
VITE_APP_NAME=TUNIT
```

`VITE_` 값은 브라우저에서 보이므로 키·DB 비밀번호를 넣지 않는다. 실제 `.env*`는 Git에서 제외하고 `.env.example`만 공유한다.

로컬 `/api` 프록시는 `127.0.0.1:8080`을 향한다. 미래 운영 환경도 같은 출처 `/api`를 Spring으로 전달하는 구성을 전제로 한다. HTTP 실패를 mock 성공으로 바꾸지 않으며 서버가 없으면 연결 오류를 표시한다. 세션·CSRF 요청 규격은 [API 계약](api-spec.md)에 있다.

## 보존과 복구 범위

기존 앱과 중단된 구현은 로컬 `.preview/`에 보존되어 있으며 Git에 포함하지 않는다. 따라서 새로 clone한 환경에는 이 백업이 없다. 디자인 참고 원본과 현재 정적 자산은 저장소에 포함한다.
