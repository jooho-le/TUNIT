# 관심 요청·초대 상태 규칙

## 관심 요청

| 현재      | 행동               | 허용 주체                          | 다음      | 연결       |
| --------- | ------------------ | ---------------------------------- | --------- | ---------- |
| 없음      | 보내기             | 활성 취향을 가진 발신자, 본인 제외 | PENDING   | 없음       |
| PENDING   | 수락               | 수신자                             | ACCEPTED  | 한 건 생성 |
| PENDING   | 거절               | 수신자                             | REJECTED  | 없음       |
| PENDING   | 취소               | 발신자                             | CANCELLED | 없음       |
| 종료 상태 | 수락·거절·취소     | 허용된 당사자                      | 409, 유지 | 중복 없음  |
| 모든 상태 | 허용되지 않은 행동 | 타인/잘못된 주체                   | 403, 유지 | 유지       |

자기 요청은 400입니다. 로컬 모드는 동일 사용자 쌍의 양방향 중복을 거절합니다. **종료 후 재요청 정책은 Notion 미확정**이므로 현재 로컬 UI에서는 과거 요청이 있는 동일 쌍도 409로 막습니다. 서버 작성 시 재요청 정책을 정하고 프론트와 계약을 함께 맞춰야 합니다.

로컬 어댑터는 요청 갱신과 연결 추가를 같은 JSON 저장에 묶습니다. 저장 전 실패를 주입하면 PENDING과 연결 없음이 유지되는 것을 테스트합니다. 이것은 PostgreSQL 트랜잭션·여러 프로세스 경합의 증거가 아닙니다. 실제 서버는 정규화된 관계쌍 유일 제약, PENDING 중복 방지, `@Transactional`, 잠금 또는 버전 제어와 롤백 테스트가 필요합니다.

UI는 대기 중인 요청에만 행동 버튼을 표시하고, 전송 중에는 잠급니다. 403/409이면 이유를 표시하고 최신 목록을 재조회합니다. 실패를 성공으로 표시하거나 변경 요청을 자동 재전송하지 않습니다.

## 초대

| 상태          | 조건                        | UI                         |
| ------------- | --------------------------- | -------------------------- |
| WAITING       | 아직 수신자가 참여하지 않음 | 링크 복사·대기·로그인/가입 |
| NEEDS_PROFILE | 참여자 중 취향 미완료       | 온보딩 후 링크 복귀        |
| NEEDS_CONSENT | 양측 공개·비교 동의 미충족  | 공개 설정·명시적 동의      |
| READY         | 양측 준비·공개·동의 완료    | 참여자만 1:1 비교          |
| EXPIRED       | 기한 경과                   | 비교 차단·새 초대          |

초대 조회에는 취향·곡·비교 점수가 없습니다. 비교 API는 참여자, 프로필, 공개·동의, 만료 여부를 매번 확인합니다. 다른 계정은 403, 대기는 409, 만료는 410입니다. 가입/온보딩의 `next`는 `/invite/:token`만 허용해 외부 주소 복귀를 막습니다.

로컬 체험의 유효기간은 **24시간으로 임시 선택**했습니다. 초대 UUID는 로컬 저장소에 존재하며 실제 보안 토큰 설계가 아닙니다. 서버에서는 고엔트로피 토큰과 해시 저장, 최종 기한·재발급 정책을 구현해야 합니다.
