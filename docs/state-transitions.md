# 관심 요청·초대 상태 규칙

[문서 안내](README.md) · [API 계약](api-spec.md) · [검증 기록](test-results.md)

2026-11-27에 사용자가 승인한 Spring P0 정책이다. 실제 Spring 필터·트랜잭션·임시 PostgreSQL에서 검증했다. 기존 브라우저 mock은 디자인 체험용 별도 저장소이며 아래 서버 정책과 완전히 동일한 인증 경계가 아니다.

## 관심 요청과 연결

| 현재 | 행동 | 허용 주체 | 결과 |
| --- | --- | --- | --- |
| 없음 | 생성 | 취향 COMPLETE인 발신자; 활성/COMPLETE/공개 상대 | 201 PENDING |
| 같은/역방향 PENDING | 생성 | 양측 | 409, 한 건 유지 |
| PENDING | 수락 | 수신자 | ACCEPTED와 현재 connection 한 건, 동일 트랜잭션 |
| PENDING | 거절 | 수신자 | REJECTED, 연결 없음 |
| PENDING | 취소 | 발신자 | CANCELLED, 연결 없음 |
| 종료 상태 | 재처리 | 해당 행동 권한이 있는 당사자 | 409, 기존 이력 유지 |
| 모든 상태 | 잘못된 행동 | 제3자·발신자의 수락 등 | 403, 상태 유지 |
| 현재 연결 있음 | 연결 해제 | 당사자 | 204, 현재 connection만 삭제 |
| 연결 없음 | 연결 해제 | 로그인 사용자 | 404 |
| 거절/취소/연결 해제 후 | 새 요청 | 새 요청 조건을 충족한 양측 | 새로운 PENDING 허용 |

자기 요청은 400, 비공개·미완료·없는 상대는 404다. 이미 연결된 상대에게 새 요청은 409다. 관심 목록의 ACCEPTED는 과거 이력이며 현재 친구 여부는 `/connections`로 판단한다.

사용자 쌍을 PostgreSQL UUID 순서로 잠근 다음 요청/연결을 조회·변경한다. V2의 부분 UNIQUE는 양방향 PENDING 한 건을 DB에서도 강제한다. 수락 후 연결 INSERT가 실패하면 먼저 flush한 ACCEPTED 변경도 롤백된다. 수락/취소 경합은 200·409, 연결 동시 삭제는 204·404이며 이력은 보존한다. 해제/재신청 경합은 해제 순서에 따라 신규 201 또는 기존 연결 409이고 중복/반쪽 연결을 만들지 않는다.

UI는 대기 중인 요청에만 행동 버튼을 표시하고 처리 중 잠근다. 실패 시 현재 목록을 확인한다. 관심 생성 응답이 끊겼으면 보낸 요청을 먼저 조회한다. 연결 해제는 확인 단계를 거치고, 응답 실패 시 현재 연결을 다시 조회한 뒤 화면을 맞춘다. 자동으로 POST/DELETE를 재전송하지 않는다.

## 초대

서버 enum은 PENDING/COMPLETED/EXPIRED/REVOKED다. 24시간·고엔트로피 토큰·해시 저장·상대 한 명·완료 중복 409를 사용한다. 토큰이 있는 GET 자체는 참여자를 연결하거나 만료 상태를 DB에 쓰지 않는다.

| 조건 | UI | 서버 동작 |
| --- | --- | --- |
| 익명 | 로그인 후 초대로 복귀 | 상태·기한만 제공, 개인정보 없음 |
| 본인 초대 PENDING | 링크 복사·대기 | 본인 complete는 400 |
| 참여할 상대의 취향 미완료 | 온보딩 | complete 409 TASTE_INCOMPLETE |
| 공개·비교 동의 부족 | 명시적 설정·동의 | complete/compare 403 |
| PENDING이고 양측 준비 | 참여 | POST complete에서 단 한 명 연결 |
| COMPLETED 참여자·양측 준비 | 1:1 비교 | 매번 COMPLETE/공개/동의/활성/기한 확인 |
| COMPLETED 제3자 | 이용 불가 | 비교 403; 완료 재사용 409 |
| 만료·없는·철회 상태 | 이용 불가·새 초대 안내 | complete/compare 404 INVITATION_NOT_FOUND |

비공개 전환·동의 철회는 다음 조회/비교에 반영된다. 지난 결과를 영속 캐시하지 않는다. 비교 동의 체크박스가 참인 명시적 사용자 행동에서만 본인 동의를 PATCH한다. 회원탈퇴·P1 초대 철회는 정책 확정 전이므로 API가 없다.

## 로컬 mock의 경계

로컬 mock은 기존 디자인 체험을 보존한다. 토큰은 브라우저에 있는 UUID, 가입은 체험용 자동 로그인, 이전 추천식은 아티스트 40%·곡 30%·태그 30%, 과거 요청이 있는 쌍의 재요청을 제한하며 만료 410·취향 미완료 422를 사용한다. 서버 검증으로 간주하지 않는다. 실제 승인 정책은 HTTP 모드와 위 Spring 계약을 따른다. P1 팔로우·공유는 로컬 UI, P2는 준비 화면이다.
