# 프론트 가독성과 행동 구분 개선

## 요청

전체 화면이 칙칙하고 글자가 작다는 피드백에 따라 프론트를 더 밝고 직관적으로 정리한다. 기존 3색과 DESIGN3의 디자인 방향을 유지한다.

## 변경 내용

- 본문 17~18px, 주요 버튼 16~17px, 입력값 17px를 기준으로 공통 가독성 스타일을 추가했다. 설명·곡 정보·설정·관심 요청 글자도 확대했다.
- 주요 버튼을 기본 상태부터 노랑으로 표시하고 보조 행동은 보라 계열로 구분했다. 선택한 아티스트·곡·장르·무드는 채운 배경과 선으로 표시한다.
- 홈에서는 노랑 ‘취향이 맞는 사람 찾기’와 보라 ‘친구와 음악 궁합 보기’를 먼저 배치한다. 내 취향·키워드·요청 목록은 그다음에 둔다.
- 랜딩은 큰 서비스 설명, 노랑 CTA, 확대된 기존 헤드셋과 보라 물감으로 구성했다. 이탤릭 워드마크·인트로·스크롤 모션은 유지했다.
- 헤더를 Tunit 워드마크와 한글 메뉴로 정리했다. 취향 입력을 완료한 사용자의 큰 화면에는 홈·사람 찾기·음악 발견 바로가기를 제공한다. 하단 릴도 한글을 주된 이름으로 쓴다.
- 로그인 버튼을 ‘로그인하기’로 바꿨다. 메뉴 초점 제어·보호 경로·기존 데이터 흐름은 유지한다.
- 실제 앱과 같은 스타일로 단일 HTML 보드 45개 상태를 재생성했다. ‘화면 보기’ 선택·더블클릭으로 한 화면을 축소 없이 확인하고 Escape로 전체 보드에 복귀할 수 있게 했다.
- 개별 화면을 보는 동안에도 Figma용 저장에는 전체 45개 상태가 원본 크기로 포함되도록 처리했다.
- 디자인 기준·화면 지도·검증 기록·보드 사용 안내를 현재 상태에 맞췄다.

## 검증 결과

- `npm test`: 앱 6개 파일, 51개 검사 통과. 메뉴 키보드 접근·보호 경로·하단 릴과 새 상단 바로가기를 통한 사람 찾기 이동을 확인했다.
- `npm run build`: TypeScript 및 Vite 프로덕션 빌드 통과.
- `node frontend/design/generate.mjs`: 보드 2개 파일, 3개 검사 통과. S01~S27·45개 상태·CSS 구문·ID·이미지/폰트 포함·개별 보기/Escape·전체 HTML 내보내기 확인.
- 내보내기 TS 소스·템플릿·전용 설정의 별도 타입 검사와 보기 도구/검사 JS 구문 검사 통과.
- React 점검에서 새 데이터 요청·조건부 Hook·인증 우회를 추가하지 않았고, 기존 병렬 데이터 로딩과 메뉴 초점 복귀를 보존했음을 확인했다.
- 개발·프리뷰·백엔드 서버는 실행하거나 재시작하지 않았다. 커밋·푸시·배포·브랜치 변경도 하지 않았다.

## 미검증 사항

- 실제 Chrome 미리보기 확인을 시도했으나 사용자 화면 변경 감지와 컴퓨터 사용 도구의 `failedToCreateImageDestination` 오류로 완료하지 못했다. 따라서 수정본의 데스크톱·모바일 표시와 모든 화면의 잘림 여부는 실측하지 못했다.
- HTML 보드의 화면 선택·저장 결과는 jsdom에서 확인했다. 실제 브라우저 다운로드 완료와 Figma 변환은 미검증이다.
- Spring·DB·Notion·배포 연결을 검증하거나 변경한 작업은 아니다.
