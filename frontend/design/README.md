# TUNIT 전체 화면 디자인 보드

**[showcase.html](showcase.html)을 브라우저에서 열면 모든 프론트 화면을 한 장에서 확인할 수 있습니다.** 서버 실행·로그인·별도 빌드가 필요 없습니다.

현재 React 화면의 실제 마크업과 CSS를 추출했습니다. S01~S27을 포함한 **45개 상태**를 흐름별로 배치했으며, 스크린샷이나 iframe으로 만든 보드가 아닙니다. 기본 색상 `#FFF21A`, `#171717`, `#A66BFF`와 DESIGN3의 타이포그래피·메뉴·하단 릴을 유지합니다.

## 보기

1. Finder에서 `frontend/design/showcase.html`을 더블클릭하거나 Chrome으로 드래그합니다.
2. 처음에는 보드 너비에 맞춰 축소됩니다. 상단의 **+/−**, **전체 맞춤**, **원본 크기 100%**로 배율을 바꿀 수 있습니다.
3. 화면을 더블클릭하면 해당 화면을 크게 봅니다. `Esc`는 전체 보기로 돌아갑니다.
4. 상단 **흐름** 선택 또는 보드 목차로 원하는 구간에 이동합니다.

각 화면의 기준 너비는 **1440px**이며 긴 페이지는 본문을 함께 볼 수 있도록 세로 길이를 다르게 지정했습니다. 랜딩은 인트로·Hero·4개 소개·최종 CTA를 장면별로 펼쳤습니다. 정적인 디자인 검토 자료이므로 페이지 안의 로그인·삭제·전송 버튼은 실행되지 않습니다.

이미지·폰트·스타일이 파일 안에 포함되어 오프라인에서도 표시됩니다. 전체 한글 폰트를 포함하므로 파일은 약 **20MB**입니다. 사용한 폰트의 라이선스도 HTML 안에 포함했습니다.

## Figma로 가져오기

권장 방법은 보기용 확대 설정과 도구 모음을 제거한 파일을 사용하는 것입니다.

1. 브라우저에서 `showcase.html`을 엽니다.
2. 상단 **Figma용 HTML 저장**을 눌러 `tunit-figma.html`을 저장합니다. 전체 보드가 원본 크기로 저장됩니다.
3. Figma Design에서 **html.to.design** 플러그인을 실행합니다.
4. **File** 탭에 `tunit-figma.html`을 드래그합니다.
5. 가져오기 화면의 viewport 너비를 보드 전체 너비인 **7600px**로 지정합니다. 기본 1440/1920px로 가져오면 가로 일부만 표시될 수 있습니다.
6. 변환 후 텍스트·여백·프레임을 수정합니다. 플러그인이 제공하는 `Create styles & variables`, `Use Autolayout` 옵션은 필요한 경우 선택합니다.

로컬 HTML 파일 반입과 viewport 설정은 [html.to.design 공식 파일 안내](https://html.to.design/docs/file-tab/)와 [가져오기 옵션 안내](https://html.to.design/docs/import-options)를 참고했습니다. 실제 Figma 반입은 이번 작업에서 실행하지 않았습니다. 폰트 누락이나 SVG 효과의 이미지 변환 여부는 반입 결과를 확인해야 합니다. 편집 시 폰트 설치를 요구하면 **Cormorant Garamond, DM Sans, Noto Sans KR**를 사용합니다.

Figma 수정은 이 정적 보드나 실제 React 코드에 자동으로 반영되지 않습니다.

| 05 친구에게 건네는 취향 | 초대 생성·대기·동의·입력 대기·공개 필요·만료·비교 결과 | 7 |
| 06 관심이 연결이 되는 순간 | 관심 작성·보낸 요청·취소·받은 요청·거절·연결 목록 | 6 |

P2 화면은 현재 앱의 준비 안내 상태를 그대로 사용했습니다. 인물·닉네임·취향·초대·관심 요청은 모두 **디자인 전용 메모리 데이터**입니다. 실제 브라우저 계정이나 Notion 데이터는 읽거나 수정하지 않습니다. 이 보드는 현재 저장소 화면을 기준으로 하며 Notion을 다시 동기화한 결과가 아닙니다.

## 파일과 다시 생성하기

| 파일 | 역할 |
| --- | --- |
| `showcase.html` | 모든 화면과 자산이 들어 있는 단일 HTML 결과물 |
| `screens.json` | 화면 ID·이름·경로·크기 목록 |
| `export.test.tsx` | 실제 React 화면 추출, 예시 상태 준비, 누락·독립성 검사 |
| `template.ts`, `atlas.css`, `viewer.js` | 보드 배치, 스타일, 선택적인 보기 도구 |
| `generate.mjs`, `vitest.config.ts` | 개발 서버 없이 실행하는 내보내기 명령 |
| `fonts.css`, `font-sources.json`, `licenses/` | 포함한 공개 폰트·출처·OFL 라이선스 |
| `prepare-fonts.mjs` | 공개 폰트를 새로 다운로드할 때만 수동 실행하는 보조 명령 |

프론트 수정 후 저장소 루트에서 실행합니다. 기존 앱 의존성이 설치되어 있어야 합니다.

```sh
node frontend/design/generate.mjs
```

이 명령은 독립적인 Vitest/jsdom 환경에서 현재 컴포넌트를 렌더링해 HTML과 목록을 다시 생성합니다. 서버나 자동 동기화를 만들지 않으며, 변경해 둔 HTML을 재생성하면 덮어쓰므로 수동 편집본은 별도로 보관하세요. 화면 경로나 상태가 추가되면 `export.test.tsx`의 목록에도 추가합니다.

폰트 파일을 갱신해야 할 때만 네트워크가 가능한 환경에서 아래 명령을 수동 실행합니다. 고정된 공개 폰트·라이선스 URL만 요청하며 프로젝트 문구는 전송하지 않습니다.

```sh
node frontend/design/prepare-fonts.mjs
node frontend/design/generate.mjs
```

## 검증 범위

- 내보내기 검사: 45개 프레임, S01~S27 포함, 미완료 로딩 제외, ID 중복·SVG 필터 참조, CSS 구문, 이미지·폰트 포함, 외부 실행 코드·저장소 접근 없음 확인.
- 디자인 내보내기 TypeScript 검사, 기존 앱 테스트 51개, 프로덕션 빌드 통과.
- 실제 Chrome에서 로컬 파일 열기, 폰트 표시와 전체 맞춤 보드 배치 확인.
- Figma 변환, 전체 45개 화면의 픽셀 단위 비교, HTML 저장 버튼의 실제 다운로드 결과는 미검증.
